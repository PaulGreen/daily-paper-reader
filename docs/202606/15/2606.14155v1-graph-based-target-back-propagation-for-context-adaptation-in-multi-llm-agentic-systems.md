## 摘要
上下文适应通过从任务反馈迭代修订可调提示，实现基于LLM系统的提示工程自动化，而无需修改模型权重。将这一范式扩展到多LLM智能体系统至关重要：现有方法存在信用分配不准确且缺乏收敛保证的问题。我们提出基于图的目标反向传播（GTBP），这是一个面向建模为有向无环图的智能体工作流的上下文适应框架。GTBP通过工作流图反向传播局部目标输出，并利用目标与输出间的差异来指导阶段性提示更新机制。理论上，我们证明GTBP的阶段性提示更新在迭代过程中趋于稳定，且一个能力足够的LLM优化器能够降低总体目标。实验上，GTBP在三个基准测试中一致超越强基线方法，同时保持了可比较的计算成本。

## Abstract
Context adaptation automates prompt engineering in LLM-based systems by iteratively revising tunable prompts from task feedback, without modifying model weights. Extending this paradigm to multi-LLM agentic systems is crucial: existing methods suffer from inaccurate credit assignment and lack convergence guarantees. We propose \textbf{G}raph-based \textbf{T}arget \textbf{B}ack-\textbf{P}ropagation (GTBP), a context adaptation framework for agentic workflows modeled as directed acyclic graphs. GTBP propagates local target outputs backward through the workflow graph and uses target--output discrepancies to guide a stage-wise prompt update mechanism. Theoretically, we show that GTBP's stage-wise prompt updates become stable over iterations, and that a sufficiently capable LLM optimizer can decrease the overall objective. Empirically, GTBP consistently outperforms strong baselines across three benchmarks while maintaining comparable computational cost.

- **研究背景**：大规模语言模型（LLM）驱动的多模块智能体系统在复杂任务中日益普遍，但人工设计各模块的上下文（提示）成本高、扩展性差。  
- **核心问题**：如何自动化地调整多LLM智能体系统中各模块的提示，使得系统整体任务表现最优？现有方法（如基于全局反思的提示优化）面临两个主要挑战：  
  - **信用分配不准确**：最终错误难以精确追溯到具体的模块提示。  
  - **收敛性缺失**：缺乏理论保证，优化过程不稳定。  
- **整体意义**：本文提出一种结构化的上下文适应框架，将多模块工作流建模为有向无环图（DAG），通过目标反向传播实现模块级信用分配，并提供理论收敛保证。

### 2. 方法论  
- **核心思想**：将代理工作流视为 DAG，每一节点为携带可调提示的 LLM 调用。借鉴差异目标传播（Difference Target Propagation），从最终输出目标出发展开反向传播，推断每个中间模块应产生的理想输出（局部目标），再利用目标-输出差异驱动提示更新，全程无需模型梯度。  
- **关键技术细节**：  
  - **工作流形式化**：系统包含 \(K\) 个并行的中间模块 \(\{M_k(x; \pi_k)\}_{k=1}^K\) 和一个输出模块 \(M_{\text{out}}(x, O_1, \dots, O_K; \pi_{\text{out}})\)。  
  - **LLM 引导的目标传播**：给定最终目标 \(y^*\)，对每个节点 \(v\) 求解目标输入 \(\hat{I}_v\)，使其在当前提示下能逼近节点目标输出 \(\hat{O}_v\)。由于该优化不可解析，采用 LLM 按模板 \(P_{\text{back}}\) 近似推断：  
    \[
    \hat{I}_v = \text{LLM}(P_{\text{back}}(\hat{O}_v, I_v, c_v))
    \]  
    其中 \(c_v\) 是节点上下文。  
  - **阶段式提示更新**：将每个模块的提示结构化为文本声明列表 \(\pi_v = \langle c_{v,1}, \dots, c_{v,m} \rangle\)。每次迭代利用一个小批次样本的 \((I_v, O_v, \hat{O}_v)\) 三元组，通过 LLM 优化器按模板 \(P_{\text{optimize}}\) 更新声明。更新机制引入两个调度参数：  
    - **声明增加间隔** \(m^+\)：每 \(m^+\) 次迭代增加一条新声明。  
    - **编辑预算衰减** \(m^-\)：每 \(m^-\) 次迭代减少可编辑声明数量，实现编辑逐步细化。  
  - **整体算法**（GTBP）：采样小批次 → 前向执行并缓存输出 → 反向目标传播 → 阶段式提示更新，循环迭代。  
- **理论分析**：在简化设定下证明：  
  - 提示更新引起的隐式权重变化量以 \(O(t^{-1})\) 收敛（稳定性）。  
  - 若 LLM 优化器能力足够，整体损失与最优损失的差距为 \(O(t^{-1})\)，即方法随迭代减小目标函数。
