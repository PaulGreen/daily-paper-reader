## 摘要
大型推荐模型（LRMs）在工业级推荐任务中已展现出可观潜力。然而，如何全面且高效地将传统信号融入这些基于Transformer的架构，仍是一项重大挑战。常规做法直接将这些信号“文本化”或创建离散的物品表征，往往导致提示词过长、内存占用高和计算开销大。为克服这些局限，我们提出“Token Factory”框架，旨在将传统信号转化为可直接被LRMs处理的“软Token”。该方法能高效整合并压缩异构输入特征，防止提示词长度膨胀，同时提升模型性能。我们详述了Token Factory的架构，并展示了在生产规模推荐环境中验证其有效性的实验结果。

## Abstract
Large Recommendation Models (LRMs) have demonstrated promising capabilities in industry-scale recommendation tasks. However, holistically integrating traditional signals into these transformer-based architectures effectively and efficiently remains a major challenge. Conventional approaches that "textualize" these signals directly or create discrete item representations often lead to excessively long prompts, substantial memory footprints, and high computational overhead. To overcome these limitations, we propose "Token Factory", a framework designed to transform traditional signals into "soft tokens" that can be directly processed by LRMs. This approach enables efficient integration and compression of heterogeneous input features, preventing prompt length explosion while enhancing model performance. We detail the architecture of Token Factory and present experimental results validating its effectiveness in a production-scale recommendation environment.

### 2. 方法论

- **核心思想**：引入 **Token Factory** 框架，将传统信号直接映射为 **软 Token（soft token）**，即不经过离散词汇表，而是通过可学习的变换生成与模型隐藏维度对齐的连续向量，作为 Transformer 的直接输入。
- **关键技术细节**：
  - 框架包含若干 **Token Maker** 模块（如观看历史 Token Maker、查询 Token Maker、候选物品 Token Maker），每个负责从一组原始特征生成固定数量的软 Token。
  - 对每个 Token Maker，输入特征先经归一化或 Embedding 查表，拼接成 $\mathbf{E}_{input}$，再通过可微映射 $G$（通常是一个 MLP）输出 $N$ 个长度为 $d_{model}$ 的软 Token。
  - 最终 prompt 演化为 `[watch_history] <emb> <emb> ... <emb> [end_watch_history] ...`，从而将原本上百 Token 的文本化序列压缩为单个或少量软 Token。
  - **序列压缩**：若需处理超长历史，可在序列维度用 MLP 做进一步压缩（如从 $N$ 降为 $M$），或借鉴 Attention Pooling 每 $K$ 个物品合并为一个软 Token。
  - 查询级（用户）特征可预先计算并缓存，大幅降低线上推理延迟。

### 6. 主要结论与发现

- **效率与效果兼得**：Token Factory 在将 prompt 长度压缩约 70% 的情况下，最终达到与文本化基线相当的 AUC；由于长度缩短可支持更大 batch size，**最终 AUC 超越基线**。
- **线上收益显著**：在生成式检索线上实验中，Unique Impressions 提升 +16.8%，对新视频尤为突出（+67.1%），同时用户满意指标（Satisfied Watchers、Satisfied Watch Time）亦获得正向增益。
- **软 Token 注意力更均衡**：通过注意力热力图分析，软 Token 使注意力分布更均匀，避免了文本化 SID 中大量 Token 完全不受关注的情况，提升了模型容量利用率。

### 7. 优点

- **高度紧凑且可预测**：输出软 Token 数量固定，不受原始特征规模影响，训练与推理资源占用可控。
- **保留信息完整性**：避免了文本化过程中的信息损失及超长序列问题。
- **架构灵活、可扩展**：Token Maker 可适配任意异构特征，支持缓存加速（查询级特征可离线预计算），为更长的用户行为序列建模提供了可能。
- **实证充分**：同时验证离线指标和线上业务指标，可信度较高。

### 8. 不足与局限

- **场景单一**：实验仅基于 YouTube 视频推荐，缺乏其他行业或任务（如电商、新闻）的验证。
- **可解释性弱**：软 Token 是不可读的连续向量，难以人工理解特征融合过程。
- **额外参数成本**：Token Maker 引入新的 MLP 等可学习模块，增加了训练参数与收敛时间。
- **压缩比与性能权衡**：论文对输出 Token 数量 $N$ 的选择多为经验设置，缺少系统的超参数敏感性分析。
- **未探索更复杂的变换器**：$G$ 主要使用简单 MLP，虽然提及可扩展至 Transformer 等结构，但未提供对比。
