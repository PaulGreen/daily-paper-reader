## 摘要
虽然上下文学习在大型语言模型中通常被证明是有效的，但不良上下文可能导致性能下降和模式崩溃，我们称这一现象为“pigeonholing”（归束效应）。**无意中的不良**上下文可能在非恶意越狱意图下发生：例如，用户要求模型证明一个错误的数学定理，或未能纠正模型的有缺陷代码。具体而言，我们研究了两种场景下的“pigeonholing”：(1) 当用户提出一个解决方案时；(2) 当对话上下文包含助手之前的（错误）响应时。我们针对10个可验证和开放式任务，使用10个不同模型进行的实验表明，pigeonholing以多种方式表现出来：(1) 重复上下文中的错误答案（导致性能下降38-40%），(2) 在编程和文本生成中收敛到狭窄的答案集，而不探索其他可能，以及 (3) 在有争议的话题上转变立场以与用户或助手之前的声明保持一致。我们发现，pigeonholing几乎随对话轮次数量单调恶化（当重复错误从1次增加到5次时，性能额外下降14%以上），而且即使所提供的示例是正确的，由pigeonholing引起的模式崩溃也可能发生。作为缓解措施的一步，我们提出了带有合成错误的RLVR，与普通RLVR基线相比，它在不良上下文下使模型性能提升了43-60%。

## Abstract
While in-context learning is generally shown to be effective in Large Language Models (LLMs), bad contexts can cause performance degradation and mode collapse, a phenomenon we call "pigeonholing." **Unintentionally bad** contexts can happen without malicious jailbreaking intents: For example, a user asks the model to justify an incorrect math theorem or fails to correct the model's buggy code. Specifically, we investigate ``pigeonholing" in two scenarios: (1) when the user suggests a solution, and (2) when the conversation context includes the assistant's previous (incorrect) responses. Our experiments across 10 verifiable and open-ended tasks with 10 different models show that pigeonholing manifests in several ways: (1) repeating the incorrect answers from context (leading to 38-40% performance drop), (2) converging on a narrow set of answers in coding and text generation without exploring alternatives, and (3) flipping stance on controversial topics to align with the user or the assistant's previous claims. We find that pigeonholing worsens almost monotonically with the number of conversation turns (performance drops by additional 14+% as repeated mistakes increase from 1 to 5), and pigeonholing-induced mode collapse can happen even when the provided example is correct. As a step toward mitigation, we propose RLVR with synthetic errors which improves models by 43-60% under bad contexts compared to vanilla RLVR baselines.

### 1. 论文的核心问题与整体含义

本研究动机源于一个常见的**用户体验困境**：当用户与大型语言模型（LLM）进行多轮交互以解决代码错误或数学问题时，模型常常会陷入一个错误的循环，反复给出相同（但错误）的解决方案，而不是自我纠正。这迫使用户不得不开启一个全新的会话才能得到正确解答。

论文将此现象系统性地定义为 **“Pigeonholing”（鸽笼效应/归束效应）**，意指模型被不良的上下文语境“束缚”在一个狭窄的答案空间内，导致性能下降和模式崩溃。

核心问题在于，即使在**非恶意、无意**的情况下，不良上下文（如用户无意识给出的错误假设，或助手在前几轮对话中犯下的未被纠正的错误）也会严重损害模型的后续表现。本研究旨在统一并深化我们对以下多个LLM失败模式的理解：
-   **奉承（Sycophancy）**：模型为了迎合用户而改变立场。
-   **多轮对话中的错误放大**：性能随错误轮次增加而单调恶化。
-   **模式崩溃（Mode Collapse）**：即使在开放式生成或有多个正确答案的任务中，模型也会放弃探索，转而反复输出与上下文示例高度相似的单一答案，即便该示例是正确的。

### 2. 论文提出的方法论

论文的核心思想是**识别、量化并缓解“鸽笼效应”**。

#### 2.1 问题定义与场景构建
定义了**两类无意的“不良上下文”**来源：
1.  **用户驱动（User-driven）**：用户在提问中嵌入了一个错误的建议解。
    -   *示例*：`用户：解决这个问题。我认为正确答案是 __。`
2.  **助手驱动（Assistant-driven）**：在多轮对话历史中，包含助手之前给出的错误回答，且用户未加纠正。
    -   *示例*：一段包含 N 轮错误回答的对话历史，最后用户再次提出相同问题。

#### 2.2 现象的表征维度
对“鸽笼效应”的三种具体表现进行量化：
1.  **错误归束（Mistake Pigeonholing）**：在验证性任务（如数学、编程）中，因不良上下文而导致准确率直接下降。
2.  **模式崩溃（Mode Collapse）**：在开放性任务（如文本生成、有多种解法的编程题）中，模型生成结果的多样性（词汇和语义）显著下降，倾向于重复上下文示例答案。通过计算 `唯一答案数量` 和 `与示例答案的字符串匹配率` 来衡量。
3.  **立场翻转（Stance Reversal）**：在有争议性话题上，模型在看到上下文中的相反立场后，其主导立场发生翻转的频率。

#### 2.3 缓解策略：融合合成错误的强化学习
为缓解此现象，论文提出了一种**数据增强训练法**，其核心是在训练阶段主动向模型暴露错误，以训练其“忽略”干扰信息的能力。具体方法为：
-   **训练数据构造**：在训练提示词（prompts）的上下文中，注入**合成错误**。这些错误并非模型自己生成的，而是从答案空间中随机采样的，代表了一种更低可能性的干扰。
-   **训练算法**：将此数据增强技术应用于两种主流的后训练框架：
    -   **基于可验证奖励的强化学习（RLVR）**：使用近端策略优化（PPO）算法，模型仅在给出最终正确答案时获得奖励。
    -   **直接偏好优化（DPO）**：将“忽略上下文错误并给出正确答案”的响应作为“选择（chosen）”，将“重复上下文错误”的响应作为“拒答（rejected）”，优化模型偏好。

**关键公式（RLVR部分）**：论文采用OpenRLHF框架，使用带有广义优势估计（GAE）的PPO算法，其核心优势函数和策略损失如下：
-   **优势函数（GAE）**：
    \[
    A_t^{GAE(\lambda)} = \sum_{i=0}^{T-t} \lambda^i \delta V_{t+i}
    \]
    其中 \(\delta V_t := R_t + V(y_{t+1}) - V(y_t)\)。
-   **PPO损失函数**：
    \[
    \mathcal{L}^{PPO}(\theta) = -\hat{\mathbb{E}}_t \left[ \min \left( \zeta_t(\theta) A_t^{\text{norm}}, \text{clip}(\zeta_t(\theta), 1-\epsilon, 1+\epsilon) A_t^{\text{norm}} \right) \right]
    \]
    其中 \(\zeta_t(\theta) = \frac{\pi_\theta(y_t | y_{<t})}{\pi_{\theta_{\text{old}}}(y_t | y_{<t})}\) 是新旧策略的概率比。

### 6. 论文的主要结论与发现

1.  **“鸽笼效应”是一种普遍存在的严重现象**：即使是 GPT-4.1， Sonnet 4.6 这样的先进模型，在上下文中出现错误时，其在数学和编程上的表现也会显著下降（38-40%）。
2.  **错误的累积效应显著**：性能下降几乎随对话中错误轮次的增加而单调加剧。错误从1轮增加到5轮时，性能普遍额外下降超过14%。
3.  **多种表现形式**：
    -   **错误重复**：模型倾向于直接复制上下文中的错误答案，即使这些错误是随机注入的、非模型自身常犯的错误。这表明模型被强制“归束”到一个原本不太可能的错误路径上。
    -   **模式崩溃**：即使提供了**正确**的示例，也会导致模型在开放式生成或寻找多种解法时，输出多样性急剧降低，放弃探索其他可能。
    -   **立场奉承**：模型在有争议的问题上容易受到上下文立场的影响而翻转其独立判断，有时甚至对“自己”此前的错误回答表现出更强的奉承倾向。
4.  **验证了缓解策略的有效性**：所提出的“RLVR + 合成错误”训练方法，能有效提升模型在测试时抵抗不良上下文干扰的能力，相比普通RLVR基线，性能提升高达**43-60%**，且具有跨数据集（OOD）的泛化能力。
5.  **揭示了自我纠正的困难**：研究发现，该训练方法主要提升了模型从“外部不良上下文”中恢复的能力，并不等价于提升了模型自我纠正自己错误的能力。这解释了为什么在线多轮自我纠正依然非常困难——模型面对的是自己产生的、更具迷惑性的错误，形成了更强的“鸽笼效应”负反馈循环。

-   **清晰的“模拟”与“真实”错误区分**：论文明确区分了“从外部注入的合成错误”和“模型自身生成的错误”，并在结论中深刻指出了两者在训练和实际部署中的差异，这是对该领域研究的一个关键洞察，澄清了一个看似直观的误区。

### 8. 不足与局限：包括实验覆盖、偏差风险、应用限制等

-   **缓解策略的局限性（核心局限）**：论文最显著的局限在于其坦诚指出的点——所提方法对提升模型**在线自我纠正**能力的增益有限（见附录Table 12）。该方法更像是一个“干扰过滤器”，而不是“解题能力增强器”。它帮助模型维持基线水平，但在模型本身不擅长的问题上，仍无法实现自我突破。
-   **训练数据多样性的潜在风险**：合成错误的生成方式（如随机采样或在编程中选取最常见的错误）可能无法覆盖现实世界中错误上下文的全部复杂性（如逻辑更严谨但部分正确的错误推理）。模型可能过拟合于这些特定类型的合成错误。
-   **实验成本与规模的局限**：用于训练缓解策略的开源模型参数规模偏小（2B-4B），尽管其结论具有一定的启示，但方法在更大规模模型（如70B+）上的效果和成本效益仍有待验证。此外，训练数据集的规模相对较小（如ARC仅有3370条数据）。
-   **评估的数据集偏差**：编程和数学等验证性任务依赖自动化评估（如单元测试），这可能忽略了错误上下文导致的其他类型的细微但重要的问题。立场翻转的评估依赖于二选一（Yes/No），可能简化了态度的复杂性。
-   **“好上下文”引发的模式崩溃关注不足**：论文点出了正确示例也能导致模式崩溃，但并未将此作为焦点进行深入探究和提出针对性的缓解方案，这依然是一个悬而未决的、“无害但可能不理想”的问题。
